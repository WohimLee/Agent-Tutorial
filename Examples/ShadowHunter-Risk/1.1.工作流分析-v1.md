## 工作流分析

### 🧩 整体流程结构图（建议版）

```mermaid
flowchart TD

A[[App / User 服务]] -- 发送客户背调申请<br/>Topic=user_req_data_verification --> MQ1[(RocketMQ<br/>Request Topic)]

MQ1 --> B[LangGraph 背调 Workflow<br/>（AI 服务 Consumer）]

subgraph G1[LangGraph 背调主流程 Orchestrator]
    B --> C[任务初始化<br/>生成 requestId / thread_id<br/>写入 MySQL Checkpoint]

    C --> D[公司名称标准化 / 唯一识别<br/>Normalize Company]

    D --> E{信息收集并行 Fan-out}

    subgraph S1[内部信息 Agent]
        E --> F1[查询内部 MySQL<br/>历史客户/交易/黑名单]
        F1 --> M1[internal_history 数据整理]
    end

    subgraph S2[海关数据 Agent]
        E --> F2[调用海关 API<br/>获取进出口记录]
        F2 --> M2[贸易行为解析与清洗]
    end

    subgraph S3[Web / Search Agent]
        E --> F3[搜索 API + 爬虫 MCP<br/>官网/新闻/评价]
        F3 --> M3[结构化信息抽取]
    end

    subgraph S4[LinkedIn Agent]
        E --> F4[LinkedIn MCP<br/>规模/行业/职位等]
        F4 --> M4[业务标签与人员信息提取]
    end

    M1 --> H[信息汇总与冲突解析]
    M2 --> H
    M3 --> H
    M4 --> H

    H --> I[风险识别 & 维度分析<br/>Risk Analysis Agent]

    I --> J[生成结构化报告 JSON<br/>360 Check Info Schema]

    J --> K[写入 MySQL + OSS<br/>保存结构化结果 & 原始证据]

    K --> L[封装 MQ 返回参数]

end

L --> MQ2[(RocketMQ<br/>Result Topic)]
MQ2 --> A

```

📎 该流程紧密契合你文档中的接口 1 & 2 逻辑
并保持了 LangGraph 的状态式调度与可恢复性

### 📊 节点逻辑再解释一下（便于团队 Review）

#### 🟦 1. Orchestrator 主流程

负责：

✔ 编排
✔ State 管理
✔ Checkpoint 恢复
✔ 错误兜底

并且：

* 每个任务绑定

  ```
  thread_id = requestId
  ```
* 所有中间状态 state 存 MySQL

---

#### 🟩 2. 信息收集 = 并行子 Agent

| Agent          | 来源      | 作用          |
| -------------- | ------- | ----------- |
| Internal Agent | MySQL   | 历史业务关系、黑名单  |
| Customs Agent  | 海关 API  | 判断真实贸易行为    |
| Web Agent      | 搜索 + 爬虫 | 获取公开信息      |
| LinkedIn Agent | MCP     | 组织规模 & 人员结构 |

LangGraph 直接 `fan-out`
提升响应速度 🚀

---

#### 🟨 3. 风险识别 Agent

输出：

* 风险等级
* 各维度评分
* 证据来源说明
* 结构化 JSON

与接口 2 中字段一一对应 ✔
