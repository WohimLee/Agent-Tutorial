## Mermaid
### 1️⃣ 总体分层架构图（从业务入口到 Tool）

```mermaid
flowchart LR

%% ===== 顶层：业务入口 & MQ =====
subgraph CLIENT[Client / Channel]
    A[[智能业务员<br/>App / CRM]]
end

subgraph MQ[RocketMQ Topics]
    IN[(clue_input_topic<br/>线索输入)]
    PROFILE[(verification_profile_update_topic<br/>画像增量结果)]
    ASK[(ask_suggestion_topic<br/>追问建议)]
end

A -->|提交线索| IN

%% ===== LangGraph 编排层 =====
subgraph G[Clue Orchestrator Graph<br/>LangGraph Graph]
    
    %% --- Subgraph 0: 线索预处理 & 归一（必须最先） ---
    subgraph SG0[Subgraph: Lead Normalize & Entity Resolve]
        N0_1[Node: ingest_and_init]
        N0_2[Node: normalize_and_type_detect<br/>提取 domain_candidates]
        N0_3[Node: customer_entity_resolver]
        N0_4[Node: profile_gap_analyzer]

        N0_1 --> N0_2 --> N0_3 --> N0_4
    end

    %% --- Subgraph 1: Email 相关（依赖 SG0；可为 domain 补充候选） ---
    subgraph SG_EMAIL[Subgraph: Email Intelligence Flow]
        N1_1[Node: email_agents<br/>企业/个人邮箱识别<br/>可写入 domain_candidates]
    end

    %% --- Subgraph 2: Domain / 官网（依赖“可信的 domain_candidates”） ---
    subgraph SG_DOMAIN[Subgraph: Domain & Website Flow]
        N2_1[Node: domain_agents<br/>选择 primary_domain<br/>DNS / WHOIS / Crawl]
    end

    %% --- Subgraph 3: 公司（可与 Email / Person / Misc 并行） ---
    subgraph SG_COMPANY[Subgraph: Company Profile Flow]
        N3_1[Node: company_agents<br/>公司名清洗 / 工商查询]
    end

    %% --- Subgraph 4: 人物（可并行） ---
    subgraph SG_PERSON[Subgraph: Person Profile Flow]
        N4_1[Node: person_agents<br/>People Search / 职位&行业匹配]
    end

    %% --- Subgraph 5: 其他线索（可并行） ---
    subgraph SG_MISC[Subgraph: Misc Intelligence Flow]
        N5_1[Node: misc_agents<br/>电话号段 / 国家风险]
    end

    %% --- Subgraph 6: 画像合并 & 风控（fan-in 汇总） ---
    subgraph SG_PROFILE_RISK[Subgraph: Profile Merge & Risk]
        N6_1[Node: merge_and_profile_update<br/>多源信号合并 & 写画像]
        N6_2[Node: risk_engine<br/>entity_existence / trade_reliability / industry_fit / final_result]
        N6_3[Node: build_incremental_result<br/>组装 incremental_result JSON]

        N6_1 --> N6_2 --> N6_3
    end

    %% --- Subgraph 7: 追问建议 ---
    subgraph SG_ASK[Subgraph: Ask Suggestion Flow]
        N7_1[Node: question_suggester<br/>基于画像缺口生成追问建议]
        N7_2[Node: finish]
        N7_1 --> N7_2
    end

    %% ===== 依赖与并行关系 =====

    %% 0 -> 并行 fan-out
    SG0 -->|基于标准化结果并行触发| SG_EMAIL
    SG0 -->|并行触发| SG_DOMAIN
    SG0 -->|并行触发| SG_COMPANY
    SG0 -->|并行触发| SG_PERSON
    SG0 -->|并行触发| SG_MISC

    %% Email 只是“可能补充域名候选”，不作为硬依赖
    SG_EMAIL -. 可补充 corp 域名候选 .- SG_DOMAIN

    %% 多源结果 -> 汇总 & 风控（fan-in）
    SG_EMAIL --> SG_PROFILE_RISK
    SG_DOMAIN --> SG_PROFILE_RISK
    SG_COMPANY --> SG_PROFILE_RISK
    SG_PERSON --> SG_PROFILE_RISK
    SG_MISC --> SG_PROFILE_RISK

    %% 风控完成 -> 追问建议
    SG_PROFILE_RISK --> SG_ASK
end

IN -->|触发 Graph 调用| G
G -->|incremental_result JSON| PROFILE
G -->|ask_suggestions| ASK

PROFILE --> A
ASK --> A
```

> 这一张图上：
>
> * **G = LangGraph Graph**（Clue Orchestrator）
> * `SG_* = Subgraph`
> * `N*_* = Node`
> * MQ 只是 I/O，不属于 Graph

### 2️⃣ Graph 内部：Node → Agent → Tool 关系

下面这张是“概念架构图”，专门说明 Node、Agent、Tool 的关系（以 Email 分支为例，其他类似）。

```mermaid
flowchart TD

%% ====== LangGraph Node 层 ======
subgraph GRAPH[LangGraph Graph: Clue Orchestrator]
    direction TB

    subgraph SUB_EMAIL[Subgraph: Email Intelligence Flow]
        direction TB
        NODE_EMAIL[Node: email_agents<br/>（负责 orchestrate 本条 Email 流）]
    end
end


%% ====== Agent 层（业务智能体 / 服务） ======
subgraph AGENTS[Agents（业务任务执行者）]
    direction TB
    A1[Agent: Email Intelligence Agent<br/>识别邮箱类型 / 提取域名]
    A2[Agent: Domain Info Agent<br/>DNS / MX / WHOIS / 域名年龄]
    A3[Agent: Email Credibility Evaluator<br/>计算 contact_credibility]
end

%% ====== Tool 层（原子能力 / 外部系统） ======
subgraph TOOLS[Tools（LLM 可调用的函数 / API）]
    direction TB

    T1[Tool: parse_email]
    T2[Tool: dns_query]
    T3[Tool: mx_lookup]
    T4[Tool: whois_lookup]
    T5[Tool: http_probe]
    T6[Tool: risk_scoring_lib]
end


%% 连接关系：Node 调用 Agent，Agent 调 Tool
NODE_EMAIL -->|调用| A1
NODE_EMAIL -->|调用| A2
NODE_EMAIL -->|调用| A3

A1 -->|使用| T1
A2 -->|使用| T2
A2 -->|使用| T3
A2 -->|使用| T4
A3 -->|使用| T6
```

可以直接照这个 pattern 把其他分支扩展：

* `domain_agents` Node → Website Probe Agent / Web Crawl Agent / Website Profile Merger → http_probe / crawl_html / extract_text / llm_extract_profile
* `company_agents` Node → Company Name Cleaner / Business Registry Agent → query_business_db …
* `person_agents` Node → People Search Agent → linkedin_search / company_employee_lookup …
* `misc_agents` Node → Phone & Location Agent → phone_geo_lookup / risk_country_db
* `risk_engine` Node → Risk Model Engine → score_* 系列 Tool

### 3️⃣ 如果你要做成 PPT / PRD 里的说明文字（摘要）

你可以在图旁边配一句解释（直接复制改下项目名就行）：

> * **Graph（Clue Orchestrator Graph）**：
>   基于 LangGraph 的线索处理总编排，从 MQ 读入线索，串联各 Subgraph，最终产出画像增量结果和对业务员的追问建议。
>
> * **Subgraph**：
>   将同一类任务（Email / Domain / Company / Person / Misc / Profile & Risk / Ask）封装为可复用的子流程，内部由一个或多个 Node 组成。
>
> * **Node**：
>   LangGraph 中的基本执行单元，负责一次完整的业务步骤，通常 orchestrate 若干 Agent 并更新 State。
>
> * **Agent**：
>   面向业务任务的智能体或服务，例如 Email Intelligence Agent、Risk Model Engine，内部会调用多个 Tool。
>
> * **Tool**：
>   面向 LLM 的原子能力封装，如 DNS 查询、HTTP 探测、工商注册信息查询、风险打分库等。
