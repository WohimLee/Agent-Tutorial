# 一、Checkpointer：LangGraph 的**短期记忆管理器**

## 1️⃣ 它解决什么问题？

LangGraph 的核心理念是：

> 图 = 有状态（stateful）的推理流程

State 在节点之间流动，但：

* 多轮对话 = 多次调用图
* 你希望调用之间**还能记住之前的状态**

所以：

### 👉 Checkpointer = 帮你“存档 State 的系统”

并支持：

| 能力                 | 说明               |
| ------------------ | ---------------- |
| 保存当前 state         | 像给游戏存档           |
| 恢复历史 state         | 带 thread_id 自动续接 |
| 多步推理中多次 checkpoint | 支持 step-by-step  |
| 多用户并发              | 每个 thread 独立     |

---

## 2️⃣ 使用方式（核心概念）

你需要三样东西：

### ✔ State —— 状态结构

```python
class State(TypedDict):
    messages: list
```

### ✔ thread_id —— 会话唯一键

```python
config={"configurable": {"thread_id": "user_123"}}
```

### ✔ checkpointer —— 后端存储

```python
checkpointer = SqliteSaver("memory.db")
graph = builder.compile(checkpointer=checkpointer)
```

---

## 3️⃣ Checkpointer 是怎么运作的？

**每次执行图：**

1. LangGraph 看有没有 `thread_id`
2. 去 checkpoint 存储里查
3. 如果存在 → 恢复 state
4. 执行节点
5. 在合适节点保存新 checkpoint
6. 下次继续用

你可以理解为：

> thread_id = 时间线
> checkpoint = 时间点

---

## 4️⃣ Checkpointer 保存的是什么？

不仅仅是 messages，而是：

✔ 整个 State（序列化 JSON）
✔ 节点执行轨迹
✔ 时间线
✔ metadata

因此它支持：

* 回放
* 调试
* 审计
* 分支推理（branch）

---

## 5️⃣ 官方提供的 Checkpointer

### ① 内存版（开发调试）

```python
from langgraph.checkpoint.memory import MemorySaver
```

特点：

| 优点      | 缺点      |
| ------- | ------- |
| 零配置     | 进程退出就没了 |
| 快       | 不能跨机    |
| 适合 demo | 不能上生产   |

---

### ② SQLite 持久化

```python
from langgraph.checkpoint.sqlite import SqliteSaver
```

| 优点    | 场景   |
| ----- | ---- |
| 单机持久化 | 小项目  |
| 零依赖   | 内部工具 |
| 性能可接受 | 个人应用 |

---

### ③ Postgres / 云数据库

| 优点    | 场景   |
| ----- | ---- |
| 支持并发  | SaaS |
| 高可靠   | 生产   |
| 可观测性强 | 企业应用 |

（实现方式与 SQLite 类似，只是 backend 不同）

---

### ④ Redis / KV 存储

| 优点    |
| ----- |
| 快     |
| 分布式   |
| 适合高吞吐 |

---

## 6️⃣ Checkpointer 的作用总结一句话

> 它保证：
> **“每次请求图，都是带着历史上下文运行的”**

而且：

✔ 你不需要手写记忆管理
✔ 多轮对话天然支持
✔ 比 langchain memory 更系统化
✔ 能存复杂推理流程，而不止 messages

# 二、Store Memory：**长期记忆系统（Knowledge Memory）**

## 1️⃣ 它解决什么问题？

Checkpointer 只保存：

> 当前线程的工作记忆

而 Store Memory 主要用于：

✔ 用户偏好
✔ 用户档案
✔ 长期事实
✔ 知识库数据
✔ 跨线程共享信息

也就是：

> 长期、结构化、可检索的记忆

---

## 2️⃣ Store Memory 的接口

最简单实现：

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()
```

支持方法：

| 方法     | 说明 |
| ------ | -- |
| put    | 写入 |
| get    | 读取 |
| search | 检索 |

---

## 3️⃣ 数据结构是什么？

核心模型：

```
namespace + key + value(JSON)
```

例：

```python
store.put(
  namespace="user_profile",
  key="user_123",
  value={"name":"Tom","likes":"coffee"}
)
```

这样你可以：

✔ 按 namespace 分类
✔ 按 key 定位
✔ 按内容检索

---

## 4️⃣ Store 可以是什么？

| 类型       | 场景   |
| -------- | ---- |
| 内存 store | demo |
| SQLite   | 轻量   |
| Postgres | 生产   |
| Redis    | 高并发  |
| 向量库      | 知识搜索 |
| 混合架构     | 大型系统 |

LangGraph 不限制 backend
你可以自由扩展

---

# 三、Checkpointer VS Store Memory

| 对比项          | Checkpointer           | Store Memory |
| ------------ | ---------------------- | ------------ |
| 作用           | 短期记忆                   | 长期记忆         |
| 是否绑定 thread  | 是                      | 不一定          |
| 保存内容         | State                  | 任意数据         |
| 典型内容         | messages / pipeline 状态 | 用户档案 / 知识库   |
| 生命周期         | 会话级                    | 系统级          |
| 是否自动接入 graph | 是                      | 需要自己访问       |
| 是否参与推理流程     | 自动                     | 手动注入 prompt  |

---

# 四、典型架构模式

## 模式 1：对话机器人

### Checkpointer

保存：

* 最近 messages
* tool results
* system 状态

### Store

保存：

* 用户偏好
* 历史事实
* 长期笔记

---

## 模式 2：Agent Workflow

### Checkpointer

用来：

✔ 恢复工作进度
✔ 支持中断/续跑
✔ 观察节点执行历史

### Store

用来：

✔ 数据资产
✔ structured memory
✔ pipeline artifacts

# 五、代码层面流程图

```
用户请求 →
  查 checkpoint →
    恢复 state →
      graph 执行 →
        需要检索长期记忆？
          是 → store.search()
        继续执行 →
      保存新 checkpoint →
响应
```

# 六、最佳实践建议

## 1️⃣ Checkpointer 的选择

| 场景              | 推荐          |
| --------------- | ----------- |
| demo / notebook | MemorySaver |
| 本地 app          | SqliteSaver |
| web 后端          | Postgres    |
| 高并发 API         | Redis + PG  |

---

## 2️⃣ Store 的设计

### 用户偏好

→ Key-Value

### 知识库

→ 向量检索

### 会话摘要

→ 存 Store
→ 减少 prompt 压力

---

## 3️⃣ 不要这样做

❌ 把所有历史消息丢给模型
❌ 用 Store 当短期记忆
❌ 用 Checkpointer 存大规模文本
❌ 没有设计 namespace

---

# 七、如果一句话总结

✔ **Checkpointer = 线程短期记忆 + 状态恢复系统**
✔ **Store Memory = 长期、跨线程结构化记忆系统**

两者结合＝可扩展、有记忆的 AI 应用基础设施。
