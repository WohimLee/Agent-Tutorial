## checkpoint

如果说 State 是第一灵魂，那 Checkpoint（检查点）就是让 State 真正“可控、可恢复、可审计”的关键机制。


### 一、Checkpoint 是什么？

Checkpoint = 状态持久化 + 执行进度保存

在 LangGraph 中：Checkpoint 会在每个节点执行后，把当前 **State + 执行位置** 保存下来

这意味着：

- 程序崩了 👉 可以继续
- 人想介入 👉 可以修改 State 再跑
- 想回放 👉 可以从任意步骤重来
- 多轮对话 👉 状态不会丢

### 二、Checkpoint 解决了什么问题？

如果没有 Checkpoint：

❌ Agent 一旦中断就得重来
❌ 无法恢复循环
❌ 无法人工介入
❌ 对话状态要自己存
❌ 调试非常痛苦

有了 Checkpoint：

✔ 恢复执行（resume）
✔ 时间旅行（time travel / replay）
✔ Human-in-the-loop
✔ 长对话持久化
✔ Agent 审计 & 追踪

### 三、Checkpoint 的核心组件
##### 1️⃣ Checkpointer（检查点存储器）

LangGraph 提供多种实现：

| Checkpointer    | 用途                |
| --------------- | ----------------- |
| `MemorySaver`   | 本地 / 调试           |
| `SqliteSaver`   | 本地持久化             |
| `PostgresSaver` | 生产                |
| 自定义 Saver       | Redis / Mongo / 云 |

```py
from langgraph.checkpoint.memory import MemorySaver
checkpointer = MemorySaver()
```

##### 2️⃣ Thread（执行线程）

Checkpoint 是 **按 Thread 保存的**

👉 thread_id = 会话 / 用户 / 任务 ID

```py
config = {
    "configurable": {
        "thread_id": "user_123"
    }
}
```


##### 3️⃣ Checkpoint 内容（存了什么？）

每个 checkpoint 包含：

- 当前 State
- 当前 节点位置
- 执行历史
- 元信息（时间、step）

你可以理解为：
```py
Checkpoint = {
  state,
  next_node,
  history,
  metadata
}
```

### 四、Checkpoint 怎么用？
##### 1️⃣ 创建 Graph + Checkpointer
```py
from langgraph.graph import StateGraph
from langgraph.checkpoint.memory import MemorySaver

graph = StateGraph(State)

# ... add nodes / edges ...

checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)
```

##### 2️⃣ 调用时指定 thread_id
```py
result = app.invoke(
    {"messages": []},
    config={
        "configurable": {
            "thread_id": "chat_001"
        }
    }
)
```

关键点：
- 同一个 thread_id
- 状态会自动接着上一次跑

##### 3️⃣ 继续执行（Resume）
```py
👉 不传 state = 从 checkpoint 恢复

app.invoke(
    None,
    config={
        "configurable": {
            "thread_id": "chat_001"
        }
    }
)
```


### 五、Checkpoint + 循环 = Agent 的核心

在 Agent 中常见结构：
```
Agent
  ↓
Router ──→ Tool
  ↑        ↓
  └────────┘
```

每一轮都会：
- 执行 Agent
- 保存 Checkpoint
- 判断是否继续
- 下轮从 Checkpoint 恢复

👉 这就是 LangGraph Agent 能“无限思考”的原因

### 六、Human-in-the-loop（Checkpoint 的杀手级能力）
场景：人工审核
```py
def human_review(state):
    if not state["approved"]:
        raise Interrupt("等待人工确认")
```

中断后：
- 前端展示 state
- 人修改 state
- 调 resume()
```py
app.invoke(
    {"approved": True},
    config={"configurable": {"thread_id": "order_123"}}
)
```
### 七、时间旅行（Time Travel）

你可以：

- 查看历史 checkpoint
- 回滚到某一步
- 用不同策略重新跑

这对：**Agent 调试、Prompt 调优、行为分析** 极其重要

### 八、Checkpoint vs 普通「存 State」

| 普通 State 存储 | LangGraph Checkpoint |
| ----------- | -------------------- |
| 你自己管理       | 自动                   |
| 只能存数据       | 数据 + 执行位置            |
| 不支持回放       | 支持                   |
| 不知道下一步      | 精确知道                 |
| 不支持中断       | 原生                   |


### 九、生产环境设计建议（非常重要）
##### ✅ thread_id 设计

- 用户对话：user_id
- 任务执行：task_id
- 多 Agent：session_id + agent_name

##### ✅ State 要可序列化

- 避免 lambda / 连接对象
- 存 ID，不存实例

##### ✅ Checkpointer 选择

- 本地调试：MemorySaver
- 服务部署：Sqlite / Postgres
- 高并发：自定义 Redis

### 十、一句话总结

Checkpoint = Agent 的“记忆 + 进度条 + 存档点”

没有 Checkpoint：
- LangGraph 只是流程图
- 有了 Checkpoint：
- LangGraph 才是真正的 Agent 操作系统
