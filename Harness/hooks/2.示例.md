如果是设计一个 **LLM / Agent Framework**，一般不会真的用 `before` / `after` 或 `pre` / `post` 去命名所有 Hook，而是会按照**生命周期（Lifecycle）**来设计。下面给你一个比较完整、接近生产环境（LangGraph、OpenAI Agents SDK、LlamaIndex 等框架思路）的 Hook 体系。

# 一个完整的 HookManager

```python
class HookManager:

    def __init__(self):
        self.hooks = {}

    def register(self, name, fn):
        self.hooks.setdefault(name, []).append(fn)

    def emit(self, name, ctx):
        for fn in self.hooks.get(name, []):
            fn(ctx)
```

注册

```python
hooks.register("pre_llm", log_prompt)

hooks.register("post_llm", log_result)

hooks.register("pre_tool", check_permission)

hooks.register("post_tool", record_tool_usage)

hooks.register("on_error", report_error)
```

执行

```python
hooks.emit("pre_llm", ctx)

response = llm(prompt)

hooks.emit("post_llm", ctx)
```

# 一个推荐的命名规范（最符合主流框架）

```text
Lifecycle
├── on_start
├── on_finish
├── on_error
│
├── pre_input
├── post_input
│
├── pre_memory
├── post_memory
│
├── pre_retrieval
├── post_retrieval
│
├── pre_rerank
├── post_rerank
│
├── pre_prompt
├── post_prompt
│
├── pre_llm
├── post_llm
│
├── pre_parse
├── post_parse
│
├── pre_tool
├── post_tool
│
├── pre_response
├── post_response
│
├── on_stream_start
├── on_stream_delta
└── on_stream_end
```

这种命名有几个优点：

* **统一性**：几乎所有阶段都采用 `pre_` / `post_` 成对出现，视觉和语义一致。
* **可扩展性**：新增阶段（如 `pre_planning` / `post_planning`、`pre_validation` / `post_validation`）时无需改变整体风格。
* **工程实践**：很多现代 Agent 框架虽然具体名字不同，但底层都是围绕“生命周期事件 + 前置/后置钩子”来设计的，因此这种命名方式最容易让其他开发者理解。
