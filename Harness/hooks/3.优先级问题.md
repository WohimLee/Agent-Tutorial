`priority`（优先级）用于**控制多个 Hook 的执行顺序**。

假设一个事件（例如 `pre_llm`）注册了很多 Hook：

```text
pre_llm
├── 安全检查
├── Prompt 改写
├── 日志
├── Token 统计
├── 缓存检查
```

**谁先执行？**

这就是 `priority` 的作用。

---

## 没有 priority

例如：

```python
hooks.register("pre_llm", log)
hooks.register("pre_llm", rewrite_prompt)
hooks.register("pre_llm", safety_check)
```

执行顺序只能依赖注册顺序：

```text
1. log
2. rewrite_prompt
3. safety_check
```

如果有一天：

```python
hooks.register("pre_llm", safety_check)

...

hooks.register("pre_llm", log)
```

整个执行顺序就变了。

大型项目里很难维护。

---

## 有 priority

例如：

```python
hooks.register("pre_llm", safety_check, priority=10)

hooks.register("pre_llm", rewrite_prompt, priority=20)

hooks.register("pre_llm", cache_check, priority=30)

hooks.register("pre_llm", log, priority=100)
```

HookManager 会排序：

```python
self.hooks[event].sort(key=lambda x: x[0])
```

执行顺序就是

```text
priority=10
↓

safety_check

priority=20
↓

rewrite_prompt

priority=30
↓

cache_check

priority=100
↓

log
```

无论谁先注册，都一样。

---

# 为什么实际项目都喜欢这样

例如一个 Agent：

```text
pre_llm
```

里面可能有十几个 Hook。

例如：

```text
Authentication

Permission

Prompt Rewrite

Memory Inject

Cache

Logging

Tracing

Token Counter

Rate Limit
```

显然：

权限检查一定要最早。

日志可以最后。

所以：

```text
Permission          10

Safety              20

Rewrite Prompt      30

Memory              40

Cache               50

Tracing             80

Logging            100
```

这样任何插件都不会互相影响。

---

# 举个实际例子

例如：

```python
def safety(ctx):
    print("安全检查")

def rewrite(ctx):
    print("改Prompt")

def log(ctx):
    print("记录日志")
```

注册：

```python
hooks.register("pre_llm", log, priority=100)

hooks.register("pre_llm", rewrite, priority=20)

hooks.register("pre_llm", safety, priority=10)
```

虽然注册顺序是：

```
log

rewrite

safety
```

真正执行：

```
安全检查

↓

改Prompt

↓

记录日志
```

---

# 如果两个 Hook 优先级一样呢？

例如：

```python
hooks.register("pre_llm", a, priority=50)

hooks.register("pre_llm", b, priority=50)
```

Python 的排序（`list.sort()`）是**稳定排序（stable sort）**。

因此：

```
先注册 a

↓

再注册 b
```

执行就是：

```
a

↓

b
```

如果反过来注册：

```
b

↓

a
```

执行就是：

```
b

↓

a
```

也就是说：

* **优先按 `priority` 排序。**
* **`priority` 相同，则保持注册顺序。**

# 推荐的优先级约定

很多项目会预留一些“档位”，避免大家都用连续数字：

| Priority | 用途                        |
| -------- | ------------------------- |
| 0–9      | 框架内部核心 Hook（尽量不要给业务使用）    |
| 10–19    | 安全、权限、认证                  |
| 20–39    | 输入处理、Prompt 改写、Memory 注入  |
| 40–59    | RAG、缓存、上下文构建              |
| 60–79    | LLM 调用相关（Tracing、Metrics） |
| 80–99    | 输出处理、格式化                  |
| 100+     | 日志、调试、统计等不影响业务逻辑的 Hook    |

这样不同团队开发的 Hook 即使互不认识，也能通过约定保持合理的执行顺序。
