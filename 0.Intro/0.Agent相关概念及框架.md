## Agent

### 1 相关概念
#### 🧩 一、Agent（智能体）核心概念

这些是最基础的：

- Agent（智能体）：能自主规划、执行任务、调用工具的智能组件。
- A2A（Agent-to-Agent）：智能体之间的通信、协作机制。
- MCP（Model Control Plane）：统一管理 agent、模型、工具的控制中枢。
- Policy（策略）：Agent 的决策逻辑，一般由大模型或强化学习组件提供。
- Memory（记忆）：Agent 在任务执行中长期或短期存储的知识，如：
    - Short-term memory
    - Long-term memory
    - Episodic memory（事件记忆）
    - Semantic memory（语义知识）
- Tools / Plugins / Actions（工具调用）：Agent 执行任务时可以调用的外部能力：API、数据库、代码执行器等。

#### 🕹 二、Agent 执行过程中的关键概念
- Reasoning（推理）
    - LLM 对任务进行思考的过程：
    - CoT（链式思考）
    - ToT（树状思考）
    - GoT（图状思考）
    - Reflection（反思与自我评估）
- Planning（规划）：Agent 分解任务、制定步骤、安排 Workflow
- Orchestration / Workflow（编排）：多 Agent 或多个步骤的任务执行流程，例如 DAG 工作流
- Delegation（任务委派）：Agent 把任务分配给其他 Agent（A2A 的关键场景）
- Evaluation（评估）：系统或专门的 Agent 对结果进行检查、评分

#### 🛠 三、Agent 的组件与结构概念
- Prompt / System Prompt（系统指令）：用于定义 agent 的角色与行为
- State（状态）：Agent 在任务执行中的内部信息
- Context（上下文）：当前任务相关信息、历史消息、Memory 集合。
- Profile（角色配置）：Agent 的“人格模板”：目标、工具、技能。

#### 🧭 四、Agent 的能力扩展概念
- RAG（检索增强生成）：Agent 通过检索文本库增强能力。
- Tool-use（工具调用）：包括：
    - Code Interpreter（代码执行）
    - Web browsing
    - API 调用

#### 🤖 五、多智能体体系（Multi-Agent System）概念
- Coordinator / Manager Agent：协调多个智能体的“管理者”
- Worker Agent：执行特定任务的“员工”
- Critic / Judge Agent：对其他 Agent 的输出打分、修正
- Supervisor / Meta-Agent：管理整个系统的“超级智能体”（如 OpenAI o1 思考型 agent）。
- Negotiation / Consensus（协商与一致性）：Agent 之间的投票、讨论、裁决机制。

#### 🏗 六、Agent 系统相关的工程概念

- Agent Framework（Agent 框架）：如：LangChain、AutoGen、CrewAI、ReAct、OpenAI MCP。
- Runtime（Agent 运行时）：提供 Agent 执行环境，如工具、文件系统、任务队列。
-  Control Plane / Data Plane：MCP = control plane，执行任务的是 data plane（工具、模型等）
- Safety & Guardrails（安全护栏）：限制 agent 行为、防止越权或风险操作


### 2 框架


| 维度                 | **Agno**                                           | **CrewAI**                           | **LangGraph**                                  | **OpenAI Swarm**              |
| ------------------ | -------------------------------------------------- | ------------------------------------ | ---------------------------------------------- | ----------------------------- |
| **框架定位**           | 多代理系统框架，注重“协作式智能体”和任务调度                            | “团队式 Agent 框架”，强调角色分工与任务流            | 图（Graph）式工作流引擎，用于复杂 Agent orchestration        | OpenAI 官方实验性轻量框架，用于多 Agent 探索 |
| **核心理念**           | Agents 协作 + 工具调用 + 状态管理                            | 每个 Agent 是一个角色（Role），组成 Crew 协同任务    | 用节点（Node）表示 Agent 或工具，用边（Edge）表示控制与数据流         | Agent 间“handoff”（交接）为核心机制     |
| **开发语言**           | Python（官方），部分 SDK 支持 TypeScript                    | Python（官方）                           | Python（官方，深度集成 LangChain）                      | Python（轻量，少依赖）                |
| **Agent 结构**       | 可定义多个 Agents + Memory + Tools + Workflow           | 通过 “Crew” 聚合多个角色化 Agents             | Graph = StateGraph (nodes, edges, transitions) | 基于函数式定义 Agent 与交接逻辑           |
