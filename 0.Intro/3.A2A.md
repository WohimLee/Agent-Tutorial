## A2A
### 一、A2A（Agent-to-Agent）到底是什么？
##### 1️⃣ 本质定义

**A2A = Agent-to-Agent 协议/范式**

它描述的是：一个 agent 如何“像调用服务一样”调用另一个 agent，而不是“一个模型调用另一个模型”。

关注点不在 Prompt，而在 Agent 级互操作。

##### 2️⃣ A2A 解决的核心问题
| 问题       | 传统方式         | A2A 方式               |
| -------- | ------------ | -------------------- |
| Agent 发现 | 手写 URL / SDK | Agent Card 自动发现      |
| Agent 调用 | 私有 HTTP API  | 标准 RPC               |
| 异步任务     | 自定义回调        | 标准 task 生命周期         |
| 流式输出     | 各家不一致        | message/stream       |
| 跨框架      | 几乎不可能        | LangGraph / ADK / 其他 |


👉 A2A 的目标是“Agent 互联网”而不是“多模型调用”

##### 3️⃣ A2A 的抽象层级
```
Model  <  Tool  <  Agent  <  Agent Network
                  ↑
                 A2A 在这里
```

### 二、LangGraph 里的 A2A：两层含义（非常关键）

LangGraph 本身不是 A2A 协议
LangGraph 是 A2A Agent 的“执行引擎 + 编排器”

必须分清两个层次 👇

#### 层次一：概念层（Agent-to-Agent 协作）

这是你在 一张 LangGraph 图里 写多 agent 系统时用到的。

这一层的核心思想: Agent = 一个可独立决策、读写状态、产出行动的节点（或子图）

>LangGraph 对应组件总览

| A2A 抽象     | LangGraph 对应组件          |
| ---------- | ----------------------- |
| Agent      | Node / Subgraph         |
| Agent 状态   | State（通常是 messages）     |
| Agent 间通信  | 共享 state / message list |
| 控制权转移      | `Command(goto=...)`     |
| Agent 调度   | Conditional Edges       |
| 多 Agent 并行 | `Send()`                |
| Agent 封装   | Subgraph                |


##### 1️⃣ Agent = Node / Subgraph
```
ResearchAgent ─┐
                ├─ Supervisor
CodingAgent  ──┘
```
- 简单 agent：一个 node
- 复杂 agent：一个 subgraph（内部有 planning / tool / loop）

👉 这是 LangGraph 对“Agent”的基本映射

##### 2️⃣ Agent 间通信 = State + Messages
```py
class State(TypedDict):
    messages: list[BaseMessage]
```

- 所有 agent 共享或部分共享 messages
- agent 不“直接对话”，而是 读写同一个对话状态

👉 这是 LangGraph 风格的 A2A 通信

##### 3️⃣ Agent handoff = Command（非常重要）
```py
return Command(
    goto="coding_agent",
    update={"messages": [ai_msg]}
)
```

- 语义是：“我这个 agent 决策完了，把上下文更新一下，然后把控制权交给另一个 agent”
- 这正是 Agent-to-Agent 控制流转移 的显式表达。

##### 4️⃣ 多 Agent 并行 = Send
```py
Send("expert_agent", expert_state)
```

- 一个 agent → 多个 agent
- 常用于：多专家投票、多角度分析、Map-Reduce 型 agent

##### 5️⃣ Supervisor / Router 模式

LangGraph 天然适合：
```
Supervisor Agent
   ├─ Research Agent
   ├─ Coding Agent
   └─ Critic Agent
```

Supervisor 本质是：
- 一个 只负责 Agent-to-Agent routing 的 agent
- 用 conditional edge 或 Command 决策下一跳

#### 层次二：协议层（真正的 A2A 协议）

- 这是 **跨进程 / 跨框架 / 跨团队** 的 A2A。
- 这一层 LangGraph 的角色: 把你的 LangGraph agent“暴露成一个 A2A Agent Service”

>协议层 A2A 的核心元素

| A2A 元素         | 含义               |
| -------------- | ---------------- |
| Agent Card     | 描述 agent 能力、输入输出 |
| /a2a/{id}      | 统一访问入口           |
| message/send   | 同步调用             |
| message/stream | 流式调用             |
| task/get       | 异步任务             |
| 标准 message     | text / parts     |



LangGraph 中的体现
##### 1️⃣ Agent Server（运行层）

每个 LangGraph assistant 自动变成：
```
https://host/a2a/{assistant_id}
```

其他 agent 可以：发现你、调用你、订阅你的流式输出

##### 2️⃣ 对 State 的要求

要兼容 A2A：
```
State 必须是 message-based
```

也就是：
- 有 messages
- 输入输出是对话片段（text parts）

LangGraph → A2A 的映射本质是：
```
A2A message ⇄ LangGraph messages state
```

### 三、一张总表：A2A × LangGraph 对照

| 维度  | A2A（协议）      | LangGraph（实现）    |
| --- | ------------ | ---------------- |
| 关注点 | Agent 互操作    | Agent 执行与编排      |
| 粒度  | Agent 服务     | Node / Subgraph  |
| 通信  | RPC / Stream | State / Messages |
| 控制流 | Task 生命周期    | Edges / Command  |
| 并行  | 多 task       | Send             |
| 发现  | Agent Card   | Assistant 元数据    |
| 部署  | HTTP 服务      | Agent Server     |


### 四、什么时候你“真的在用 A2A”？
❌ 还不算 A2A

- 多 prompt
- 多 chain
- 多 tool
- 一个 agent 调另一个函数

✅ 算 A2A
- 一个 agent 把任务交给另一个 agent
- agent 之间 有清晰边界和职责
- agent 可以 被独立部署和复用
- agent 可被 外部 agent 通过协议调用（进阶）
